# todorxoi — телеграм-бот «тодо бичиг»

Бот переводит калмыцкий текст между тремя формами записи и рисует
настоящее вертикальное письмо картинкой.

```
калмыцкая кириллица ──модель──► транслитерация ──правила──► тодо бичиг ──рендер──► PNG
        хальмг                     xalimaq                   ᡍᠠᠯᡅᡏᠠᡎ            🖼
```

Под каждым ответом — время работы и кнопки 👍 / 👎; по 👎 бот просит
правильный вариант и складывает пару «что выдал бот / как надо» в базу.
Это и есть способ собрать данные на дообучение.

## Логика работы бота

У пользователя есть **режим** — что делать с присланным текстом.
Переключается кнопками внизу или командами. Что именно прислали
(кириллицу, латиницу или уже тодо бичиг) бот определяет сам по
юникод-диапазонам, указывать не нужно.

### 1. `/translit` — кириллица → транслитерация

1. Текст режется на слова регуляркой (дефис внутри слова не разделяет:
   `Моңһл-Күрә` — одно слово). Пробелы, пунктуация и цифры не трогаются.
2. Каждое слово сперва ищется в **точном словаре** проверенных пар,
   вшитом в чекпойнт: там, где он есть, он надёжнее модели.
3. Чего нет в словаре — предсказывает **модель**: посимвольный seq2seq,
   BiGRU-энкодер + attention-декодер, greedy-декодирование.
4. Регистр восстанавливается отдельно (модель обучена на строчных).

В ответе видно, сколько слов взято из словаря, а сколько предсказано —
полезно, чтобы понимать, насколько ответу стоит доверять.

### 2. `/todo` — кириллица или транслитерация → тодо бичиг

Если пришла кириллица, сначала отрабатывает шаг 1. Дальше транслитерация
переводится в юникод тодо бичиг по таблицам соответствия с контекстными
правилами (`h`/`k`/`x` и `g`/`γ`/`q` выбираются по следующей гласной, а
если гласной рядом нет — по гармонии гласных всего слова). Дефис
превращается в узкий неразрывный пробел `U+202F` — так в настоящем письме
отделяются суффиксы и частицы.

Юникод тодо бичиг отобразится только если на устройстве есть подходящий
шрифт. Квадратики в ответе — не ошибка бота, для этого и есть режим
картинки.

### 3. `/image` — любая из трёх форм → картинка

Шрифт не умеет вертикальный режим сам, поэтому каждая строка рисуется
горизонтально и поворачивается на 90° по часовой: левый край становится
верхним, чтение слева-направо превращается в чтение сверху-вниз. Строки,
не влезающие в высоту столбца, переносятся по словам (только по обычному
пробелу — `U+202F` неразрывный, его рвать нельзя). Готовые столбцы
выстраиваются слева направо.

Очень вытянутую картинку Telegram не примет как фото — такая уходит
документом. Слишком большая ужимается по большей стороне.

> ⚠️ **Картинка выглядит как набор несвязанных букв?**
> Значит, Pillow в этом окружении собран **без Raqm**.
>
> Монгольское письмо курсивное: буква имеет разные формы в начале, середине
> и конце слова, соседние буквы сливаются в один вертикальный стержень.
> Выбирает нужную форму не шрифт, а движок раскладки — HarfBuzz, к которому
> Pillow ходит через библиотеку Raqm. Без него Pillow **молча** рисует
> каждую букву в изолированной форме: похоже на текст, но читать нельзя.
>
> Проверка:
> ```bash
> python -c "from PIL import features; print(features.check('raqm'))"   # надо True
> ```
> Лечение — поставить Pillow из PyPI (в колёсах оттуда Raqm есть; в сборках
> из conda и системных пакетов часто нет):
> ```bash
> pip install -U --force-reinstall Pillow
> ```
> Бот проверяет это на старте и пишет в лог, а вместо нечитаемой картинки
> отвечает ошибкой — лучше честно отказать, чем прислать мусор. Режимы
> `/translit` и `/todo` работают и без Raqm.

### Обратная связь

Под ответом кнопки 👍 / 👎.

* 👍 — оценка сразу пишется в базу, кнопки заменяются на «оценено».
* 👎 — оценка пишется, и бот переходит в состояние ожидания: следующее
  текстовое сообщение уйдёт не в перевод, а в поле `correction` того же
  запроса. `/cancel` выходит из ожидания, минус при этом остаётся —
  «этот ответ плохой» само по себе полезная информация.

Одна оценка на пару (запрос, пользователь): повторный клик перезаписывает
предыдущую, а не плодит строки.

### Время работы

Под каждым ответом — общее время и разбивка по шагам: `модель`,
`translit→тодо`, `рендер`. Меньше секунды показывается в миллисекундах.

### Команды

| Команда | Что делает |
|---|---|
| `/start` | приветствие и меню |
| `/help` | описание логики (то же, что здесь, но короче) |
| `/translit`, `/todo`, `/image` | переключить режим; можно сразу с текстом: `/todo хальмг улс` |
| `/mode` | какой режим включён |
| `/cancel` | отменить ввод исправления |
| `/stats` | статистика (только админы) |
| `/export [corrections]` | выгрузка фидбэка в CSV (только админы) |

## Куда сохраняется фидбэк

Два слоя, намеренно дублирующих друг друга:

1. **SQLite** — `data/todorxoi.sqlite3`, таблицы `requests` (что попросили,
   что получилось, сколько заняло) и `feedback` (оценка + исправление).
   Из него считается `/stats` и делается `/export`.
2. **JSONL** — `data/events.jsonl`, append-only, по json-строке на событие.
   Страховка на случай, если файл БД потеряется при переезде: восстановить
   можно всё.

> **Про «логи есть на хостинге».** Логи хостинга это не заменяют: они
> ротируются, обрезаются и не предназначены для того, чтобы потом строить
> из них датасет. Если бот крутится в Docker или на PaaS с эфемерным
> диском, **папку `data/` обязательно нужно примонтировать как volume** —
> иначе весь собранный фидбэк исчезнет при первом же рестарте.
> В `docker-compose.yml` это уже сделано.

Выгрузка для дообучения: `/export corrections` — CSV только с теми
строками, где человек прислал правильный вариант (`input_text`,
`bot_translit`, `bot_todo`, `correction`).

## Запуск локально

```bash
git clone https://github.com/vbadmaev1/todorxoi.git
cd todorxoi

python3 -m venv .venv && source .venv/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cpu   # CPU-сборка, ~200 МБ вместо ~800
pip install -r requirements.txt

cp .env.example .env     # и впишите BOT_TOKEN
python -m bot.main
```

Проверить ядро без телеграма:

```bash
python -c "import core; r = core.process('Хальмг улс', 'todo'); print(r.translit, r.todo, r.elapsed_ms)"
```

## Тесты

```bash
python -m tests.smoke
```

Прогоняет бота «на сухую»: сессия Bot API подменяется заглушкой, в
диспетчер скармливаются настоящие `Update`. Ни токена, ни сети не нужно.
Проверяются все три режима, кнопки 👍/👎, приём исправления, `/cancel`,
админские команды и реакция на мусор на входе.

## Деплой

**Docker (проще всего):**

```bash
cp .env.example .env     # впишите BOT_TOKEN и ADMIN_IDS
docker compose up -d --build
docker compose logs -f
```

**Без Docker (systemd):** см. `deploy/todorxoi.service` — там инструкция
в комментариях.

Бот работает через long polling: ни домен, ни сертификат не нужны, хватит
любой машины с исходящим интернетом. Экземпляр должен быть **ровно один** —
два процесса с одним токеном будут отбирать апдейты друг у друга.

### Сколько это ест

Модель — около 430 тыс. параметров, чекпойнт 2 МБ, CPU хватает с большим
запасом. Основной расход памяти — сам torch (~300–500 МБ RSS). На VPS с
1 ГБ помещается, но впритык; 2 ГБ комфортно. `TORCH_NUM_THREADS=1` не
случайность: на маленькой машине несколько потоков только мешают.

## Переменные окружения

Все — в `.env.example` с комментариями. Обязательная одна: `BOT_TOKEN`.
Стоит сразу заполнить `ADMIN_IDS` (свой id — у `@userinfobot`), иначе
`/stats` и `/export` не будут работать ни у кого: так выгрузку не сможет
скачать случайный человек.
