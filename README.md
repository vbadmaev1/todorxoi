# todorxoi — телеграм-бот «тодо бичиг»

Бот переводит калмыцкий текст между тремя формами записи и рисует
настоящее вертикальное письмо картинкой.

```
калмыцкая кириллица ──модель──► транслитерация ──правила──► тодо бичиг ──рендер──► PNG
        хальмг                     xalimaq                   ᡍᠠᠯᡅᡏᠠᡎ            🖼
```

Под каждым ответом — время работы и кнопки 👍 / 👎; по 👎 бот просит
правильный вариант и складывает пару «что выдал бот / как надо» в базу.
Это и есть способ собрать данные на дообучение.

## Логика работы бота

У пользователя есть **режим** — что делать с присланным текстом.
Переключается кнопками внизу или командами. Что именно прислали
(кириллицу, латиницу или уже тодо бичиг) бот определяет сам по
юникод-диапазонам, указывать не нужно.

### 1. `/translit` — кириллица → транслитерация

1. Текст режется на слова регуляркой (дефис слово не разрывает — что с ним
   делать, решается дальше). Пробелы, пунктуация и цифры не трогаются.
2. Слово целиком ищется в **точном словаре** проверенных пар, вшитом в
   чекпойнт: там, где он есть, он надёжнее модели.
3. Если не нашлось и в слове есть дефис — см. ниже про составные слова.
4. Остальное предсказывает **модель**: посимвольный seq2seq, BiGRU-энкодер
   + attention-декодер, greedy-декодирование.
5. Регистр восстанавливается отдельно (модель обучена на строчных).

В ответе видно, сколько слов взято из словаря, сколько предсказано и
сколько составных разобрано — полезно, чтобы понимать, насколько ответу
стоит доверять.

#### Дефис: составное слово или суффикс

Дефис в калмыцкой орфографии означает две разные вещи, и обрабатывать их
одинаково нельзя.

**Составное слово** — две самостоятельные основы: `көвүн-күүкн`, `эк-эцк`,
`ах-дү`, `өдр-сө`. Модель на таком токене целиком выдаёт мусор
(`көвүн-күүкн` → `köböüngöükken`), а по частям всё чисто.

**Суффикс через дефис** — `һазр-ән`, `кел-ән`. Здесь наоборот: `-ән` это
возвратно-притяжательный суффикс, отдельным словом он не существует. Целый
токен модель отрабатывает верно (`γazar-bēn`), а деление дало бы неверное
`γazar-ani`.

Правило, которое различает эти случаи без списка суффиксов:

> делим по дефису только тогда, когда **каждая** часть есть в словаре как
> самостоятельное слово; иначе отдаём токен модели целиком.

Части составного слова соединяются **обычным пробелом** — это два полных
слова, и в письме они разделяются широким пробелом. Дефис, дошедший до
тодо бичиг (из словарной пары вроде `zer-zeb` или из суффикса), становится
узким неразрывным пробелом `U+202F`.

| вход | результат | почему |
|---|---|---|
| `көвүн-күүкн` | `köböün köüken` | обе части в словаре → делим |
| `моңһл-күрә` | `mongγolkürē` | весь токен есть в словаре → берём как есть |
| `һазр-ән` | `γazar-bēn` | `ән` не слово → модель на целом токене |

### 2. `/todo` — кириллица или транслитерация → тодо бичиг

Если пришла кириллица, сначала отрабатывает шаг 1. Дальше транслитерация
переводится в юникод тодо бичиг по таблицам соответствия с контекстными
правилами (`h`/`k`/`x` и `g`/`γ`/`q` выбираются по следующей гласной, а
если гласной рядом нет — по гармонии гласных всего слова). Дефис
превращается в узкий неразрывный пробел `U+202F` — так в настоящем письме
отделяются суффиксы и частицы.

Юникод тодо бичиг отобразится только если на устройстве есть подходящий
шрифт. Квадратики в ответе — не ошибка бота, для этого и есть режим
картинки.

### 3. `/image` — любая из трёх форм → картинка

Шрифт не умеет вертикальный режим сам, поэтому каждая строка рисуется
горизонтально и поворачивается на 90° по часовой: левый край становится
верхним, чтение слева-направо превращается в чтение сверху-вниз. Строки,
не влезающие в высоту столбца, переносятся по словам (только по обычному
пробелу — `U+202F` неразрывный, его рвать нельзя). Готовые столбцы
выстраиваются слева направо.

Очень вытянутую картинку Telegram не примет как фото — такая уходит
документом. Слишком большая ужимается по большей стороне.

#### Настройки картинки (`/settings`)

Цвет текста, цвет фона и размер шрифта — у каждого пользователя свои,
лежат в таблице `user_settings` и переживают перезапуск бота. Палитра
одна на проект и объявлена в `core/todo_image.py` (`PALETTE`,
`BG_PALETTE`), чтобы телеграм-слой не заводил собственный список.

Два случая обрабатываются особо:

* **Прозрачный фон** — чтобы накладывать надпись на свои изображения.
  Такая картинка отправляется **документом**: фото Telegram пережимает в
  JPEG, а в JPEG нет альфа-канала, и прозрачность превратилась бы в
  чёрный прямоугольник — ровно то, ради чего её включали.
* **Совпавшие цвета текста и фона** — рисовать пустой прямоугольник
  бессмысленно, поэтому рендер откатывается на чёрное по белому и
  говорит об этом под картинкой. Бот предупреждает и раньше — сразу при
  выборе цвета в `/settings`.

Высота столбца масштабируется вместе с кеглем: иначе на крупном шрифте
в строку влезало бы слишком мало букв и перенос срабатывал бы не там.

#### Почему рендер не использует рисование текста из Pillow

Монгольское письмо курсивное: у буквы разные формы в начале, середине и
конце слова, соседние буквы сливаются в один вертикальный стержень. Нужную
форму выбирают таблицы GSUB/GPOS в шрифте, а применяет их движок раскладки —
HarfBuzz.

Pillow умеет ходить в HarfBuzz, но только если собран с библиотекой Raqm.
Если нет — **молча** рисует изолированные формы: похоже на текст, но читать
нельзя. И это свойство конкретной сборки, а не вашего кода: в Google Colab
и в колёсах с PyPI Raqm есть, в conda и системных пакетах часто нет. То
есть один и тот же скрипт даёт правильную картинку в ноутбуке и мусор на
сервере, без единой ошибки в логах.

Поэтому `core/shaper.py` зовёт HarfBuzz напрямую (`uharfbuzz`) и
растеризует глифы через FreeType (`freetype-py`), а Pillow остаётся только
складывать готовые растры. Результат одинаковый в любом окружении.

Порядок выбора движка:

1. **uharfbuzz + freetype-py** — основной, стоит в `requirements.txt`;
2. **Pillow с Raqm** — если первых нет, но со сборкой повезло;
3. **Pillow без Raqm** — буквы не соединяются; бот всё равно отдаёт
   картинку, но подписывает предупреждением, чтобы её не приняли за
   правильное письмо. `STRICT_SHAPING=1` запрещает и это.

Что используется сейчас — видно в логе при старте бота и в `python -m
tests.smoke`. Режимы `/translit` и `/todo` от раскладки не зависят вообще.

### Обратная связь

Под ответом кнопки 👍 / 👎.

* 👍 — оценка сразу пишется в базу, кнопки заменяются на «оценено».
* 👎 — оценка пишется, и бот переходит в состояние ожидания: следующее
  текстовое сообщение уйдёт не в перевод, а в поле `correction` того же
  запроса. `/cancel` выходит из ожидания, минус при этом остаётся —
  «этот ответ плохой» само по себе полезная информация.

Одна оценка на пару (запрос, пользователь): повторный клик перезаписывает
предыдущую, а не плодит строки.

### Время работы

Под каждым ответом — общее время и разбивка по шагам: `модель`,
`translit→тодо`, `рендер`. Меньше секунды показывается в миллисекундах.

### Команды

| Команда | Что делает |
|---|---|
| `/start` | приветствие и меню |
| `/help` | описание логики (то же, что здесь, но короче) |
| `/translit`, `/todo`, `/image` | переключить режим; можно сразу с текстом: `/todo хальмг улс` |
| `/mode` | какой режим включён |
| `/settings` | цвет текста, фон (в т.ч. прозрачный), размер шрифта |
| `/cancel` | отменить ввод исправления |
| `/stats` | статистика (только админы) |
| `/export [corrections]` | выгрузка фидбэка в CSV (только админы) |

## Куда сохраняется фидбэк

Два слоя, намеренно дублирующих друг друга:

1. **SQLite** — `data/todorxoi.sqlite3`, таблицы `requests` (что попросили,
   что получилось, сколько заняло) и `feedback` (оценка + исправление).
   Из него считается `/stats` и делается `/export`.
2. **JSONL** — `data/events.jsonl`, append-only, по json-строке на событие.
   Страховка на случай, если файл БД потеряется при переезде: восстановить
   можно всё.

> **Про «логи есть на хостинге».** Логи хостинга это не заменяют: они
> ротируются, обрезаются и не предназначены для того, чтобы потом строить
> из них датасет. Если бот крутится в Docker или на PaaS с эфемерным
> диском, **папку `data/` обязательно нужно примонтировать как volume** —
> иначе весь собранный фидбэк исчезнет при первом же рестарте.
> В `docker-compose.yml` это уже сделано.

Выгрузка для дообучения: `/export corrections` — CSV только с теми
строками, где человек прислал правильный вариант (`input_text`,
`bot_translit`, `bot_todo`, `correction`).

## Запуск локально

```bash
git clone https://github.com/vbadmaev1/todorxoi.git
cd todorxoi

python3 -m venv .venv && source .venv/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cpu   # CPU-сборка, ~200 МБ вместо ~800
pip install -r requirements.txt

cp .env.example .env     # и впишите BOT_TOKEN
python -m bot.main
```

Проверить ядро без телеграма:

```bash
python -c "import core; r = core.process('Хальмг улс', 'todo'); print(r.translit, r.todo, r.elapsed_ms)"
```

## Тесты

```bash
python -m tests.smoke
```

Прогоняет бота «на сухую»: сессия Bot API подменяется заглушкой, в
диспетчер скармливаются настоящие `Update`. Ни токена, ни сети не нужно.
Проверяются все три режима, кнопки 👍/👎, приём исправления, `/cancel`,
админские команды и реакция на мусор на входе.

## Деплой

**Docker (проще всего):**

```bash
cp .env.example .env     # впишите BOT_TOKEN и ADMIN_IDS
docker compose up -d --build
docker compose logs -f
```

**Без Docker (systemd):** см. `deploy/todorxoi.service` — там инструкция
в комментариях.

Бот работает через long polling: ни домен, ни сертификат не нужны, хватит
любой машины с исходящим интернетом. Экземпляр должен быть **ровно один** —
два процесса с одним токеном будут отбирать апдейты друг у друга.

### Если деплой падает по размеру

`pip install torch` с PyPI на Linux ставит сборку **с CUDA**, даже когда
видеокарты нет: сам torch 1.2 ГБ плюс пятнадцать пакетов `nvidia-*` ещё на
3.2 ГБ. Пять с лишним гигабайт не влезают почти ни в один недорогой тариф,
а замечаешь это не сразу — пока зависимости лежат в кеше, всё работает, и
сборка ломается только когда `requirements.txt` изменится и кеш сбросится.

В `requirements.txt` поэтому прописан индекс PyTorch с CPU-сборками.
Проверить, что приехало нужное:

```bash
python -c "import torch; print(torch.__version__)"   # ждём 2.x.y+cpu
```

Если видите `+cu130` — индекс не подхватился (бывает, когда платформа
ставит зависимости своим способом). Тогда поставьте torch отдельной
командой до основных зависимостей:

```bash
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
```

На хостинге без консоли ту же команду обычно можно задать как build
command. В `Dockerfile` это уже сделано отдельным слоем.

### Сколько это ест

Модель — около 430 тыс. параметров, чекпойнт 2 МБ, CPU хватает с большим
запасом. Основной расход памяти — сам torch (~300–500 МБ RSS). На VPS с
1 ГБ помещается, но впритык; 2 ГБ комфортно. `TORCH_NUM_THREADS=1` не
случайность: на маленькой машине несколько потоков только мешают.

## Переменные окружения

Все — в `.env.example` с комментариями. Обязательная одна: `BOT_TOKEN`.
Стоит сразу заполнить `ADMIN_IDS` (свой id — у `@userinfobot`), иначе
`/stats` и `/export` не будут работать ни у кого: так выгрузку не сможет
скачать случайный человек.
